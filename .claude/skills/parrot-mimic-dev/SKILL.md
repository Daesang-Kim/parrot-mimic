# parrot-mimic 개발 가이드

앵무새가 사용자의 말을 듣고 목소리를 변조해서 따라 말해주는 모바일 웹 장난감/게임.
이 문서는 이 저장소에서 작업할 때 따라야 할 기초 설계와 개발 방향이다. 새로운 결정이
생기면 이 문서를 갱신한다.

## 1. 프로젝트 한 줄 정의

마이크로 음성을 녹음 → 여러 프리셋 중 하나로 목소리를 변조 → 앵무새 캐릭터가 변조된
목소리로 즉시 재생. 서버 없이 브라우저에서 전부 처리되는 클라이언트 전용 웹 앱.

## 2. 핵심 사용자 흐름

```
[화면 진입]
   -> 앵무새 캐릭터 + "눌러서 말하기" 버튼
[마이크 권한 요청] (최초 1회, 사용자 탭 제스처 안에서 AudioContext 시작)
   -> 거부 시: 권한 필요 안내 + 재요청 버튼으로 폴백
[녹음] (버튼 누르고 있는 동안 또는 탭-토글 방식, MediaRecorder / getUserMedia)
   -> 녹음 중 파형/레벨 애니메이션으로 피드백
[변조 프리셋 선택] (로봇 / 아기 / 외계인 / 거인 / 다람쥐 등, 녹음 전후 선택 가능)
   -> Web Audio API 그래프로 실시간 또는 녹음 후 처리
[재생] (앵무새 캐릭터가 입을 벙긋거리며 변조된 목소리 재생)
   -> 다시 녹음 / 다른 프리셋으로 재생 / (확장) 저장·공유
```

## 3. 기술 스택 (결정됨)

- **프레임워크**: React + Vite. 컴포넌트 기반으로 캐릭터/녹음 버튼/프리셋 선택 UI를
  분리하기 쉽고, 생태계가 풍부해 이후 상태관리·라우팅이 필요해져도 확장이 쉽다.
- **언어**: TypeScript 권장 (오디오 파이프라인 타입 안전성 확보). JS로 시작해도 무방하나
  가능하면 처음부터 TS로 설정한다.
- **음성 녹음/처리**: 브라우저 네이티브 **Web Audio API** (`AudioContext`,
  `MediaStreamAudioSourceNode`, `BiquadFilterNode`, `WaveShaperNode`,
  `AudioWorkletNode`) + `MediaRecorder`/`getUserMedia`. 외부 오디오 라이브러리는
  최소화하되, 피치 시프트가 네이티브 노드만으로 부족하면 `soundtouchjs` 같은 경량
  라이브러리를 AudioWorklet 안에서 사용하는 것을 검토한다.
- **PWA**: `vite-plugin-pwa`로 처음부터 설정. manifest(아이콘, 세로 방향 고정,
  standalone display) + 서비스워커로 정적 자산 캐싱 → 홈 화면 설치, 오프라인 재실행 지원.
- **배포**: 정적 호스팅(Vercel/Netlify/GitHub Pages 등). 서버/백엔드 없음 — 모든 처리는
  클라이언트에서 끝난다. 계정/서버 저장 기능이 생기기 전까지 백엔드를 추가하지 않는다.
- **테스트**: 오디오 로직은 순수 함수(프리셋 파라미터 계산 등)로 분리해 유닛 테스트
  가능하게 하고, UI는 필요 시 Playwright로 스모크 테스트(마이크는 mock).

## 4. 폴더 구조 (제안)

```
/src
  /audio          # AudioContext 세팅, 프리셋별 노드 그래프 생성 함수 (순수 로직)
  /components     # ParrotCharacter, RecordButton, PresetPicker 등
  /hooks          # useMicRecorder, useAudioGraph 등
  /assets         # 캐릭터 이미지/스프라이트, 아이콘
  main.tsx / App.tsx
/public
  manifest.webmanifest, icons/
```

오디오 처리 로직(`/src/audio`)은 React에 의존하지 않는 순수 TS 모듈로 유지한다 —
프리셋 추가/테스트가 쉬워지고, 나중에 프레임워크를 바꿔도 재사용 가능하다.

## 5. 음성 변조 프리셋 설계

프리셋은 `{ id, label, pitchSemitones, filterChain }` 형태의 데이터로 정의하고,
`/src/audio/presets.ts` 한 곳에서 관리한다. 새 프리셋 추가는 이 배열에 항목을
추가하는 것만으로 끝나야 한다 (UI/재생 로직은 프리셋 목록을 순회할 뿐 개별 분기를
갖지 않는다).

MVP 기본 프리셋 예시: 로봇(디스토션+링모듈레이션), 아기(피치업+포먼트 축소),
거인(피치다운), 외계인(피치업+비브라토). 정확한 파라미터는 구현하면서 청감 테스트로 조정한다.

## 6. 모바일/브라우저 호환성 주의사항

- iOS Safari는 사용자 제스처(탭) 콜백 내부에서만 `AudioContext`를 생성/resume할 수
  있다 — 페이지 로드 시 미리 만들어두지 말고, 첫 버튼 탭에서 생성한다.
- 마이크 접근은 HTTPS(또는 localhost)에서만 동작한다. 배포 환경은 항상 HTTPS.
- `getUserMedia` 미지원/권한 거부 케이스에 대한 명확한 안내 UI를 항상 준비한다.
- 화면은 세로 고정을 기본으로 하고, 터치 타겟은 충분히 크게(버튼 최소 44px).
- 사운드 재생 관련 자동재생 정책 때문에 결과 재생도 사용자 액션(탭) 직후에 이뤄지도록
  흐름을 짠다.

## 7. MVP 범위 (합의됨)

**포함**: 마이크 녹음 → 여러 변조 프리셋 중 선택 → 앵무새 캐릭터가 변조된 소리로 재생.
프리셋 선택 UI 포함. 최소한의 캐릭터 애니메이션(정적 이미지 + 재생 중 입 벙긋 정도는 OK).

**제외 (다음 단계)**: 점수/레벨/컬렉션 시스템, 녹음 저장·공유(영상/GIF), 다중 캐릭터,
계정/서버 저장, 일일 챌린지.

## 8. 로드맵

1. **Phase 1 (MVP)**: 위 범위. 프리셋 3~5개, 기본 캐릭터 1종, PWA 기본 설정.
2. **Phase 2**: 캐릭터 애니메이션 고도화, 프리셋 확장, 결과 공유(파일 다운로드/Web
   Share API).
3. **Phase 3**: 게임화 요소(점수, 컬렉션, 챌린지), 필요 시 계정/서버 도입 검토.

## 9. 코딩 컨벤션

- 오디오 그래프 생성 함수는 부수효과 없는 순수 함수로 작성하고, 실제 `AudioContext`
  연결은 훅(`useAudioGraph`)에서만 수행한다.
- 컴포넌트는 프레젠테이션(캐릭터, 버튼, 프리셋 목록)과 로직(훅)을 분리한다.
- 새 의존성 추가 전에 Web Audio API 네이티브 기능으로 해결 가능한지 먼저 검토한다.
- 커밋 메시지는 무엇을 바꿨는지보다 왜 바꿨는지를 담는다.

이 문서는 저장소의 실질적인 개발 방향이 바뀔 때마다(스택 변경, 범위 조정 등) 함께
갱신한다.
